# Fordix

Mod Minecraft **Forge 1.20.1** (Forge 47.x, Java 17) d'Omneria : bibliothèque d'interface
(`client/gui`, identité visuelle « Voidframe », écrans vanilla redessinés dans
`client/gui/vanilla`), panneaux créés par les admins en jeu (`/fordix panel ...`, `panel/`),
notifications serveur (`/fordix notify`, annonces automatiques, `notification/`) et onglets
Guides de l'inventaire (`client/guide`). Installé côté client **et** serveur (canal réseau).

## Branches

- **`dev`** : branche de développement. Tout nouveau travail part de `dev` et y est poussé.
- **`main`** : version officielle du projet. Ne jamais y pousser directement ; on n'y fusionne
  `dev` que lorsque l'utilisateur le demande explicitement.

## Build et tests

- `./gradlew build` compile le mod et lance les tests JUnit (`src/test`).
- Le projet cible **MinecraftForge**, pas NeoForge, malgré le plugin Gradle
  `net.neoforged.moddev.legacyforge` : utiliser les API `net.minecraftforge.*` de Forge 47.
- La CI (`.github/workflows/build.yml`) compile à chaque push et publie le jar du mod comme
  artefact `fordix-jar`, à télécharger depuis le run GitHub Actions pour tester en jeu.
- Test en jeu : `client/devtest/DevTest` (actif seulement si la variable `FORDIX_DEVTEST` est definie) ouvre un
  monde plat, parcourt HUD, ecrans et infobulles et enregistre une capture de chacun dans `run/fordix-shots`.
  En local : `xvfb-run -a -s "-screen 0 1280x720x24" env FORDIX_DEVTEST=1 LIBGL_ALWAYS_SOFTWARE=1
  MESA_GL_VERSION_OVERRIDE=4.5 MESA_GLSL_VERSION_OVERRIDE=450 ./gradlew runClient` (mettre
  `onboardAccessibility:false` dans `run/options.txt`). La CI le lance (job `ingame-test`) et publie les
  captures en artefact `ingame-screenshots` ; il echoue si le jeu plante. Ajouter un `Step` pour tout nouvel ecran.
- Avec Twilight Forest et Create dans le client de dev : `./gradlew runClient -PdevMods` (télécharge les deux mods
  via cursemaven/Modrinth, uniquement pour ce test local ; jamais utilisé par la CI ni la release).
- Règles de rareté : les règles par défaut de `RarityRules` complètent toujours celles du serveur (`withBuiltins`) ;
  les règles du serveur passent en premier, donc une règle explicite garde la main.
- Dans un conteneur cloud Claude, les dépôts Maven de Forge sont souvent bloqués et seul
  Java 21 est installé : si le build local échoue pour ces raisons, s'appuyer sur la CI.

## Publier une version

1. Passer `mod_version` à la nouvelle version dans `gradle.properties`, committer, pousser sur `dev`.
2. À la demande de l'utilisateur, fusionner `dev` dans `main` (avance rapide). Le workflow `release.yml` voit le
   `gradle.properties` poussé sur `main`, crée tout seul le tag `vX.Y.Z` (identique à `mod_version`) et publie la release.
   Un tag poussé à la main reste possible et donne le même résultat ; `workflow_dispatch` sur `main` rattrape une version
   (Actions > Release > Run workflow). Les sessions Claude ne peuvent pas pousser de tag (403) : ne pas essayer.
3. `.github/workflows/release.yml` publie `fordix-X.Y.Z.jar` + `.sha256` en release GitHub ; le
   VPS l'installe dans le modpack puis sur le serveur (voir `scripts/vps/README.md`).

Changer le protocole réseau (`PROTOCOL_VERSION` dans `PanelNetwork`) oblige joueurs et serveur à
avoir la même version : le serveur ne prend le nouveau jar qu'à son redémarrage.

## Interface Voidframe (client)

- `client/gui/vanilla` : écrans de conteneurs redessinés (`VoidframeScreens`, `VoidframeStations`), HUD
  (`VoidframeHud` vie/faim, placement par glisser-deposer dans `HudLayoutScreen` avec aimant `HudSnap`, `VoidframeGauges` XP/armure/air/boss, `VoidframeDurability`), forme commune des
  barres (`Chevron`, `BarShape`), recoloration des textures vanilla (`TextureRecolor`, `Duotone`).
  `HudLayoutScreen` liste aussi le HUD que Fordix ne dessine pas : chat, barre d'objets, scoreboard, effets, titres et tout overlay
  Forge d'un autre mod (`ExtraHud` : mesuré en le dessinant hors écran, déplacé/masqué par ses événements de rendu, sauvé dans
  `fordix-hud-extras.json`), plus la minicarte JourneyMap (`JourneyMapHud`, par réflexion sur ses réglages, position `Custom`).
  `HudSlots` donne un accès unique aux trois. Chaque élément se redimensionne (carré du coin, molette, + / -) : facteur `scale` autour du coin haut-gauche (`HudPlacement.begin/end`, `HudSlot.scale`, taille `sizePercent` pour JourneyMap). Le chat est un seul élément : historique (overlay) et barre de texte (écran de chat) partagent le même décalage et la même taille (`ExtraHud.onChat*`, clics réinjectés en coordonnées d'origine). Le chat Voidframe (`client/chat` : `ChatLog` relève les lignes du chat vanilla à chaque tick, `ChatKind`/`ChatTab` les classent, `ChatPanel` dessine onglets, historique, têtes, heures et barre de saisie ; option `voidframeChat`) remplace l'overlay et l'écran de chat vanilla, qui continuent d'envoyer et de recevoir. `InfoHud` (`client/hud`) ajoute trois panneaux déplaçables, redimensionnables et masquables (`fordix:coordinates` : X/Y/Z, direction, biome ; `fordix:performance` : FPS, TPS et ping (latence de la liste des joueurs, « -- » en solo), le TPS estimé par `TpsMeter` à partir des paquets de temps du serveur, ou lu sur le serveur intégré en solo ; `fordix:target_block` : icône, nom et identifiant du bloc visé ; `fordix:target_mob` : créature visée, deux panneaux séparés), cachés avec F3. Chaque ligne de ces panneaux s'active dans `HudLinesScreen` (option `[hudLines]`, `FordixConfig.hudLine`). Trois autres panneaux : `fordix:gear` (durabilité et munitions des mains), `fordix:clock` (réclame une horloge dans l'inventaire, la boussole une boussole : option `hudRequireItems`; heure réelle, heure et phase du jeu, météo), `fordix:compass` (direction et distance du point d'apparition ; les repères sont ceux de JourneyMap) ; la cible affiche aussi l'outil et la dureté du bloc visé ou la vie de la créature. Profils de HUD : 3 emplacements remplis depuis `HudLayoutScreen`, `HudProfileActions`/`HudProfiles` (`fordix-hud-profiles.json`), touche F8 pour passer au suivant (la minicarte JourneyMap n'en fait pas partie). Chat : onglet Privés (`ChatKind.PRIVATE`), recherche Ctrl + F (`ChatSearch`), son à la mention (`chatMentionSound`). Autres ajouts du HUD : `fordix:effects` (liste des effets de potion avec temps restant, remplace les icônes vanilla : option `hudEffectsList`), armure portée dans `fordix:gear`, créature visée de loin (`FarTarget` : rayon jusqu'à `hudTargetRange` blocs, 20 par défaut, arrêté par le premier bloc ; sert au panneau et à la touche de la fiche ; panneaux de cible de largeur fixe de 200 px, bord gauche stable, texte coupé à la largeur : un cadre qui suivait son texte se recentrait et sortait de l'écran quand on l'avait posé au bord), aperçu sous la cible (`ContainerMemory` : contenu du dernier coffre/tonneau/shulker ouvert, vu que le client ne le reçoit qu'à l'ouverture ; cadre, objet au sol, équipement d'une créature, disque de jukebox), alertes (`HudAlerts`, `AlertLatch` : objet presque cassé, arc sans flèche, TPS bas), apparence (`hudOpacity`, `hudCompact`) dans `HudOptionsScreen`, profil Combat automatique (`CombatSwitch`, `HudProfileActions.autoTick`, option `autoCombatProfile`). Redimensionnement : largeur et hauteur séparées (`scale` et `scaleY` ; 0 = identique), poignées coin/droite/bas dans `HudLayoutScreen`, molette ou + / - par 5 % (Maj 1 %, Ctrl largeur, Alt hauteur) ; la colonne de réglages est au milieu du bord gauche. Liste Tab Voidframe (`PlayerListHud` : têtes, noms par équipe, ping, en-tête et pied envoyés par le serveur, colonnes ; déplaçable, option `voidframePlayerList`). Nombres de dégâts flottants (`DamageNumbers`, `DamageTracker` : lus sur la vie des créatures proches, option `damageNumbers`). Recherche et tri d'inventaire (`InventoryTools`, `SortPlan` : inventaire de survie, coffres, tonneaux, shulkers ; Maj + Trier trie le sac ; clics espacés de 2 par tick ; option `inventoryTools`). Infobulles : verdict global face à l'objet porté (`GearCompare`). `HeldItemHud` ajoute le modèle 3D de l'objet à gauche de la ligne du nom de l'objet tenu. Le client de dev `-PdevMods` inclut aussi JourneyMap.
- Wikis en jeu (`wiki/` côté serveur, `client/wiki` + `WikiScreen` côté client) : les guides pointent par défaut vers des sites web ; un admin peut les copier dans le jeu avec `/fordix wiki import <wiki> <adresse de la page>` (`importlinks` copie aussi les pages liées, `list`, `remove <wiki> [page]`, `license <wiki> <texte>`, `importsite <wiki> <adresse>` : un site de documentation qui n'est pas un MediaWiki (MineColonies) copié de proche en proche depuis sa première page, `SiteImporter` : liens du même dossier, `<main>` ou corps sans menus, une seule version du jeu quand le site écrit chaque texte pour chaque version (`data-versions`), images WebP/SVG ignorées ; `importall <wiki> <items|mobs|all>` : la page de chaque objet et créature du mod de ce nom, une toutes les 0,35 s, ce que le wiki n'a pas est ignoré, et un nom qui mène à une autre page (« Oak_Planks » vers « Planks ») laisse une redirection). Traduction : `/fordix wiki translate <wiki> <langue> <adresse du wiki dans cette langue>` (ex. `translate minecraft fr https://fr.minecraft.wiki`) crée le wiki `<wiki>_<langue>` : pour chaque page du wiki, `WikiImporter.translate` lit son titre dans l'autre langue (`prop=langlinks`), importe cette page-là (mêmes `asOf`/`javaOnly`) et laisse le nom anglais y mener ; Sans wiki dans l'autre langue : `/fordix wiki autotranslate <wiki> <langue> [estimate]` traduit les pages déjà importées avec l'API Claude (`WikiTranslator`, HTTP direct sans SDK ; clé `[wiki] anthropicApiKey` de `fordix-common.toml` ou variable `ANTHROPIC_API_KEY` du serveur, modèle `translationModel` ; lignes envoyées en tableau JSON et rendues à l'identique, titres et noms de pages conservés, reprise là où elle s'est arrêtée, `estimate` donne le prix approximatif) dans le même wiki `<wiki>_<langue>`. `ClientWiki.localized` fait lire ce wiki aux joueurs dont le jeu est dans cette langue (fiches d'objet et de créature, repli sur l'anglais si la page manque). Un wiki est réglé pour la version du jeu du serveur : à sa création il note la version (`gameVersion`), et le wiki `minecraft` est figé deux semaines après la sortie de cette version (`asOf`, via `SharedConstants`) et ne garde que l'édition Java (`javaOnly`, `EditionFilter`) ; `/fordix wiki asof <wiki> <AAAA-MM-JJ|off>` règle la date d'un autre wiki (par exemple celle de la version du mod), `/fordix wiki javaonly <wiki> <on|off>`. Avec une date, `WikiImporter` demande la révision de la page à cette date (`prop=revisions`, puis `oldid`), suit les redirections de l'époque (`WikiPage.redirectTo`) et ignore ce qui n'existait pas encore. Le wiki porte le nom du mod (`minecraft`, `twilightforest`, `mowziesmobs`) : l'onglet Guides de ce mod ouvre alors le wiki du serveur au lieu d'un lien web, et Maj + G sur un objet ouvre sa page. `WikiImporter` lit l'API MediaWiki (un wiki installé dans un dossier, comme `http://benimatic.com/tfwiki/index.php/Main_Page`, garde ce dossier dans son adresse : `wikiRoot`) (`action=parse`), `HtmlToMarkup` convertit le HTML en `PageMarkup` (titres, paragraphes, puces, lignes de tableau, images), `ImageStore` enregistre les images en PNG dans `config/fordix/images` (aussi utilisables à la main dans les pages des admins : `@image fichier.png | légende`), `WikiStore` garde les pages dans `config/fordix/wiki/<wiki>/`. Une page est allégée à l'envoi (`PageCleaner`, sans toucher à la copie stockée : notes d'édition, légendes qui sont des noms de fichiers, lignes de tableau identiques fusionnées, tableaux qui répètent les mêmes chiffres, sections sans intérêt en jeu, texte de l'autre édition, coupe à 22 000 caractères), et l'écran du wiki a sommaire cliquable, sections repliables, zoom des images, catégories (objets/blocs/entités, ou dossier d'un site : `WikiService.categoryOf`, colonne de l'index), favoris et pages récentes (`WikiMemory`). Le client demande tout à la demande (liste, index, page, image, recherche faite par le serveur sur le texte de toutes les pages), en paquets de 24 ko (`WikiChunks`) ; protocole réseau 9. Le texte reste celui du wiki : chaque page garde son adresse et le wiki sa licence, affichées sous le titre. Fiches : Maj + G sur un objet ouvre `ItemSheetScreen` (recettes lues dans le jeu ; si le wiki du mod est importé, un bouton bascule le bas de la fiche entre les utilisations et la page du wiki, `ClientWiki.pageFor`) ; Maj + G en visant une créature (sans écran ouvert) ouvre `EntitySheetScreen` : table de butin (requête `LOOT` du canal wiki, le serveur écrit la table en JSON avec le sérialiseur du jeu, `LootSummary` en tire objet, quantités, probabilité et conditions : tué par un joueur, Butin, étiquette, autre table) et page du wiki de la créature à côté (le combat, pour un boss `forge:bosses`). Roue d'interaction des créatures apprivoisées (`client/pet/PetWheelScreen`, `WheelGeometry` pur et testé ; touche à maintenir `petWheel`, R par défaut ; élément `fordix:pet_wheel` de `HudLayoutScreen` : déplaçable, redimensionnable et masquable (masqué = roue désactivée), par un overlay vide qui sert à le lister, en visant une créature `OwnableEntity` dont on est le propriétaire) : sept secteurs, glisser puis relâcher (ou clic, ou touches 1 à 7) ; Suis-moi / Reste ici / Inventaire (cheval) / Rappeler / Relâcher (deuxième clic de confirmation) passent par `ServerboundPetActionPayload` et `pet/PetService` (propriétaire et distance vérifiés côté serveur), Nourrir et Renommer (étiquette renommée en main) sont le clic droit normal du jeu fait par le client ; un secteur inutilisable est grisé avec sa raison ; protocole réseau 9. Les pages des admins gagnent `- puce`, `@image` et `## sous-titre` ; `PageView` les dessine.

- Écran d'administration (`FordixAdminScreen`, ops) : envoi de notifications, planification (`AdminStore`,
  `NotificationScheduler`, sauvegardée dans `fordix-admin.json` du monde), modèles et éditeur de panels.
- Guides : onglets de l'inventaire (`GuideTabs`), écran Guides ouvert depuis le menu pause, bouton réservé aux opérateurs, le bouton Progrès du menu pause est retiré pour tous (`GuidesScreen` : pages du serveur
  `GuidePage`/`PageMarkup` seulement, les guides des mods sont les onglets de l'inventaire ; stockées dans `AdminStore`, édités dans l'onglet Pages de l'admin, envoyées par
  `ClientboundGuidePagesPayload`), indice Maj + G dans l'infobulle des objets d'un mod avec guide (`GuideHints`) ; Maj + G ouvre la scène Ponder de l'objet (Create 0.5.x, `PonderScenes`, par réflexion) quand il en a une, sinon sa fiche (`ItemSheetScreen`, `ItemFacts` : recettes, usages et caractéristiques lus dans le jeu, sans réseau ; un clic sur un objet ouvre sa fiche). Un lien `url:` peut contenir `{objet}` (page du wiki de l'objet) ; sans entrée « minecraft » dans la liste, `GuideTabs` ajoute un guide vanilla vers minecraft.wiki ; l'option client `guideHints` masque la ligne d'indice.
- Livre de bienvenue (item `fordix:welcome_book`, `welcome/`) : liste d'étapes `[welcomeBook] steps` de `fordix-common.toml`
  (advancement, command, guides, manual), récompense facultative, donné à la première connexion ou par `/fordix book`.
  L'onglet Livre de l'écran d'administration remplace ces étapes et la récompense (`AdminStore.welcomeSteps/welcomeReward`, sans
  redémarrage) ; « Fichier config » revient à `fordix-common.toml`.
- Plein écran fenêtré (`BorderlessFullscreen`, option `borderlessFullscreen` de l'onglet Jeu) : F11, ou la touche « plein écran » réglée du jeu, retire la bordure de la fenêtre et la place sur le moniteur où elle est, sans changement de mode vidéo ; le jeu traite cette touche et sort avant tout évènement, donc un `glfwSetKeyCallback` posé devant le sien l'intercepte ; en quitter redonne position, taille et bordure. Raccourcis : toutes les touches du mod sont des `FordixKeyMapping` (un `KeyMapping` dont `same` ne signale que la même touche avec les mêmes Maj/Ctrl/Alt et dont `hasKeyModifierConflict` est nul : Forge compare sinon la touche seule et la touche Ctrl seule, et Controlling affiche ces deux tests comme des conflits ; reste côté jeu la ligne d'une touche seule (F, échanger les mains) qui se compare à notre Ctrl + F par `same` de Forge, sans qu'on puisse l'éviter) de la catégorie Fordix, réglables dans Options > Contrôles (pas d'onglet de raccourcis dans les réglages Fordix) avec Maj, Ctrl ou Alt (`KeyModifier`) ou sans aucune touche (non assignée) ; Maj + G (`OPEN_GUIDE`) et Ctrl + F (`SEARCH_FIELD`, chat et inventaires) sont des défauts, pas des règles codées : donner à chaque touche le contexte où elle sert (`IN_GAME` pour ce qui n'agit qu'en jeu, `GUI` pour la recherche, `GUIDE_CONTEXT` pour la fiche) : le contexte universel de Forge fait signaler Ctrl + F comme conflit avec Ctrl et F seules (écran des contrôles, mod Controlling) ; tester avec `FordixClient.pressed`, jamais avec `hasShiftDown`, et masquer l'indice quand `isUnbound()`.
- Les réglages joueur sont éditables en jeu (bouton Config de la liste des mods, `FordixSettingsScreen`) : onglets Apparence, HUD, Chat, Jeu et Administration (ops seulement), « Réinitialiser l'onglet » remet les valeurs par défaut de l'onglet ouvert ; un nouveau réglage se range dans un onglet (`buildAppearance`/`buildHud`/…) avec `toggle`/`choice`, ce qui l'inscrit aussi à la réinitialisation.
- Le serveur peut imposer la liste des onglets Guides (`[guides] tabs` dans `fordix-common.toml`).

## Conventions

- Le code serveur (`panel/server`, `panel/PanelSpec`) ne doit pas référencer de classes client ;
  le code client n'est appelé qu'à travers `DistExecutor` (voir `PanelNetwork`).
- Les calculs sans dépendance Minecraft (ex. `client/gui/layout/Layout`) restent en Java pur
  pour être testables avec JUnit sans lancer le jeu.
- Tous les textes affichés par le mod passent par `Tr` (`Tr.c` composant traduit côté destinataire, `Tr.s` texte client) et les
  fichiers `assets/fordix/lang/en_us.json` et `fr_fr.json` (clés préfixées `fordix.`) : ne jamais écrire un texte en dur. Les
  retours serveur de l'écran d'administration voyagent sous la forme `Tr.encode(clé, args…)`. Ajouter une clé aux deux fichiers.
  Restent volontairement en français : les valeurs des configs (étapes du livre, libellés de guides) et les étiquettes techniques
  des destinataires dans l'historique des notifications.
